# Code Atlas 交互逻辑优化建议

> 文档状态：建议稿，尚未实施。  
> 编写日期：2026-09-03。  
> 分析基线：当前工程 `a912c03`、用户提供的 element-plus 页面截图，以及本次对当前工程内置示例的交互检查。  
> 范围：仅讨论交互逻辑，不涉及配色、字体、间距、装饰风格，也不包含代码实现。

## 1. 核心结论

当前产品已经具备目录浏览、文件搜索、依赖图、影响范围和分析面板等能力。主要问题不在于缺少更多按钮，而在于这些能力组合使用时，没有共享一套稳定、可解释、可返回的交互规则。

最典型的断点是：

1. 在目录概览里选中文件，详情栏更新了，画布却没有对应的文件对象。
2. 搜索是为了定位文件，但搜索条件继续限制画布，导致该文件的影响关系被排除。
3. 下钻目录会同时改变粒度、筛选和隔离状态，但没有一个动作能够恢复进入前的上下文。
4. 分析结果能跳转，却可能跳到错误成员、跳到不可见文件，或丢失原分类和列表位置。
5. 数字虽然存在，却没有充分说明统计范围，也缺少继续查看明细的操作。

第一轮优化应优先保证三个结果：

- 用户选择的对象一定正确、可见。
- 用户知道当前查看的范围、对象和关系方向。
- 用户深入查看后，可以回到刚才的位置继续工作。

本建议不把产品扩展为完整 IDE，也不增加调用图、源码编辑、自动修复或云端上传等能力。

- 侧栏宽度调整已有键盘操作能力，不应在后续调整中退化。

## 3. 用户任务与目标流程

### 3.1 任务 A：接手陌生工程，理解结构

用户希望回答：工程分成哪些部分、应该从哪里开始、一个目录与其他目录有什么联系。

建议流程：打开工程 → 目录概览 → 查看目录摘要 → 进入目录 → 查看文件 → 返回上一级或原概览。

成功标准：

- 能区分目录内部依赖与跨目录依赖。
- 下钻不会把用户突然带入不可理解的大量文件。
- 返回后能继续探索相邻目录，不需要重新设置粒度或找回视角。

### 3.2 任务 B：修改一个文件前，检查影响

用户希望回答：哪些文件直接依赖它、进一步会涉及谁、影响是否跨越目录边界。

建议流程：搜索文件 → 选择准确路径 → 查看“谁依赖它” → 调整跳数 → 查看明细 → 进入关联文件 → 返回原文件。

成功标准：

- 搜索文件名不会把相关文件排除。
- 影响数量与当前展示规则一致，范围外关系不会被默默省略。
- 从任何入口选择同一个文件，都得到一致的结果。

### 3.3 任务 C：沿依赖理解实现

用户希望回答：这个文件使用哪些文件、继续阅读哪个文件最有帮助。

建议流程：入口点或文件 → “它依赖谁” → 直接依赖列表 → 选择依赖文件 → 继续追踪 → 返回。

成功标准：即使一个入口点没有任何受影响文件，也能沿它的依赖继续阅读，不会停在“0 个文件受影响”。

### 3.4 任务 D：排查循环依赖或疑似死代码

用户希望回答：具体问题是什么、涉及哪些对象、为什么出现在结果中、下一项在哪里。

建议流程：分析分类 → 结果预览 → 查看组或具体文件／导出符号 → 在图中定位 → 返回原结果位置 → 下一项。

成功标准：

- 点击的成员就是选中的成员。
- 不需要每检查一项都重新打开分类、滚动和查找。
- 结果用语保留推断边界，不把疑似结果表达成已确认缺陷。

## 5. 统一交互模型

### 5.1 四个主状态应独立表达

| 用户的问题 | 状态 | 建议定义 |
|---|---|---|
| 我在看哪里 | 浏览范围 | 当前仓库、当前目录，以及显式目录／文件类型条件 |
| 我看多细 | 展示粒度 | 文件，或相对当前浏览目录的第 1／2／3 层子目录 |
| 我关注谁 | 焦点对象 | 无、文件、循环组；导出符号作为文件内的具体关注项 |
| 我看什么关系 | 关系模式 | 它依赖谁／谁依赖它，以及当前跳数 |

搜索词、面板位置和画布视角也是状态，但不应暗中改变上述四项的业务含义。

“目录层数”与“关系跳数”分别描述包含关系与依赖关系，应使用不同名称，不再把两者笼统称为“层级”。

### 5.2 推荐三种主工作状态

| 工作状态 | 主要对象 | 允许的主操作 | 默认关系范围 |
|---|---|---|---|
| 工程浏览 | 当前目录中的文件或目录 | 展开、下钻、筛选、调整粒度、选择文件 | 当前浏览范围；说明范围外依赖数量 |
| 文件关系 | 一个明确文件及其关联文件 | 切换关系方向、调整跳数、查看明细、继续选择关联文件 | 全仓库中已解析的关系，默认包含范围外关联 |
| 循环组检查 | 一个循环组及全部成员 | 查看组内关系、选择成员、返回结果 | 完整循环组，不因原目录筛选而缺成员 |

采用这一规则的原因：选择文件是“开始研究一个对象”，不等于“把工程浏览范围永久改为这个文件”。

文件关系和循环组检查进入时保存来源上下文，退出后恢复原浏览范围。界面应说明“关系覆盖全仓库”或“包含当前目录外关联”，避免用户误认为原筛选仍限制关系分析。

这里的“全仓库”仅指本次成功分析的代码文件和已解析依赖，不包括所选目录以外的代码、外部包或无法识别的动态关系。

### 5.3 选择与来源上下文

每次进入文件关系或循环组检查，至少记录：

- 当前仓库及分析结果版本。
- 来源工作状态、浏览目录、显式筛选条件、展示粒度。
- 原焦点对象、关系方向、跳数。
- 侧栏展开状态、滚动位置。
- 画布平移与缩放；条件允许时保留该视图的布局位置。
- 分析面板是否打开、分类、列表滚动位置、当前条目。

搜索结果跳转还应保留搜索词与结果位置，允许通过明确的“返回搜索结果”恢复；不需要让每次输入都进入导航历史。

### 5.4 不可违反的交互约束

1. 同一时刻只有一个明确的主焦点对象，侧栏、画布、详情栏一致。
2. 焦点对象必须可见；不能只有详情栏更新。
3. 仅输入搜索词不改变工程分析结果，也不改变关系计算范围。
4. 改展示粒度不改变分析数据；改跳数不改变浏览目录。
5. 下钻与返回成对；清空筛选不能充当返回导航。
6. 筛选不能把焦点对象悄悄删除；不适用时应切换工作状态或清楚提示。
7. 统计标明对象单位和范围，不能用全仓库数量冒充当前视图数量。
8. 同一文件的重复点击保持选择，不把“再次确认目标”解释为取消选择。
9. 悬停只预览，不提交选择，不写导航历史，不触发全图重新布局。
10. 修改条件、切换面板和新分析不得让旧异步结果覆盖更新后的用户状态。

## 6. 搜索与筛选

对应问题：I-02、I-03、I-10、I-13。

### 6.1 将搜索定义为“定位文件”

推荐默认行为：

1. 输入搜索词时展示文件结果，原画布和已提交焦点保持不变。
2. 保留现有路径匹配、忽略大小写和空格分词规则；这一轮不顺带更换匹配算法。
3. 结果显示完整路径，避免不同目录下同名文件无法区分。
4. 默认搜索本次分析的全仓库文件，并明确标注搜索范围。
5. 点击结果或按 Enter 提交选择后，进入文件关系状态，搜索结果收起。
6. 搜索词可作为返回结果的上下文保留，但不再成为画布硬筛选条件。
7. 清除搜索词只清除定位查询，不清除目录、文件类型和当前文件选择。

后续可增加“搜索当前浏览范围”，但必须让用户明确选择，不应因为曾经下钻过目录而静默改变搜索范围。

### 6.2 显式筛选只用于限定工程浏览范围

保留现有集合逻辑：

- 同类条件之间取并集，例如 `src` 或 `tests`。
- 不同类条件之间取交集，例如选定目录中的 `.tsx` 文件。
- 当前浏览目录进一步限定这些条件的作用范围。

每个生效条件都可以单独移除；“清空筛选”只清显式条件，不等于返回仓库根，也不等于清除选择历史。

从目录下钻改变的是浏览目录，不再把目录导航塞进普通筛选条件。这样“返回上一级”和“移除一个筛选”才有不同且稳定的含义。

### 6.3 不再使用含糊的“隔离”表达两种任务

需要明确区分：

| 操作 | 保留什么 | 用途 |
|---|---|---|
| 仅显示筛选结果 | 满足显式条件的文件，以及结果内部的依赖 | 看某个范围内部结构 |
| 查看文件关系 | 焦点文件、所选方向和跳数内的关联文件 | 研究一个文件的依赖或影响 |

第一轮建议保留前者作为工程浏览中的范围控制，以文件关系状态承接后者；不要再让一个“隔离”复选框同时决定二者。

没有显式条件时，“仅显示筛选结果”不可用，并说明前置条件。零命中时显示空状态，不能给空图继续执行自动取景。

### 6.4 范围外目标的处理

推荐统一规则：从搜索或分析列表明确选择范围外文件时，进入完整文件关系状态，临时展示该目标和关联文件，不改写来源筛选。

反馈示例：“正在查看当前目录外的文件；返回后保留原浏览范围。”

返回时恢复原目录、类型条件和列表位置。若用户希望把它变为新的浏览位置，提供另一个明确动作“浏览所在目录”，不要把临时定位变成永久范围修改。

### 6.5 可选的范围内关系模式

此能力不作为第一轮前置条件。若后续增加“只看当前浏览范围”，需要满足：

- 先在完整已解析依赖图中计算关系，再解释其中范围内、范围外的成员。
- 不要先删除范围外文件再计算影响，否则跨范围路径可能被误判为不存在。
- 如果两个范围内文件通过范围外文件连接，应标明路径经过范围外；不能让数量存在而关系线消失得无从解释。
- 必须始终保留焦点文件，范围外身份明确可见。

## 7. 目录浏览、下钻与返回

对应问题：I-01、I-05、I-10。

### 7.1 目录树与画布的操作分工

| 操作 | 推荐行为 |
|---|---|
| 点击侧栏目录行或展开箭头 | 只展开／折叠目录树 |
| 对目录执行“在画布中查看” | 改变工程浏览目录，形成一次导航 |
| 点击画布目录节点 | 进入该目录，形成一次导航 |
| 点击文件 | 进入该文件的关系状态 |
| 点击已选文件 | 保持当前选择，不重新布局 |
| 悬停文件或目录 | 显示预览，不改变主焦点 |

“在画布中查看”应有鼠标和键盘均可操作的入口，不能只藏在双击、右键或悬停中。

### 7.2 下钻粒度

进入目录后，优先展示其直接子目录与直属文件，逐步展开复杂结构。直属文件不能因目录聚合而被漏掉，也不能被错误归到其他路径。

建议将目录粒度解释为“相对当前目录”的层数，并在提示中写清：例如当前位于 `packages`，目录 1 层展示其直接子目录，而不是重新解释为仓库根的一层。

对于规模较小的目录，可以直接显示文件；阈值应通过真实仓库测试确定。现有超过 200 文件默认聚合的策略可作为初始参考，不应被视为已验证的通用可读性上限。

用户显式选择粒度后，普通筛选变化和悬停不得擅自覆盖该选择。

### 7.3 返回有两种不同语义

| 动作 | 含义 |
|---|---|
| 上一级 | 浏览路径移动到父目录 |
| 返回 | 恢复上一条导航记录，可能是原文件、目录、循环组或分析结果 |

例如：从循环列表定位文件后，“返回”回到该循环列表，而不是简单打开文件的父目录。

面包屑用于明确跳到某一级目录；不能代替来源历史。

### 7.4 目录折叠规则

- 搜索结果出现时可临时展开命中路径，但不要持续强制全树展开。
- 用户手动折叠后，该操作立即生效；普通重新渲染不应把它展开。
- 外部选择某个文件时，可以展开其祖先，以满足“目标可见”。
- 离开搜索或返回来源时，恢复之前的展开和滚动状态。
- 目录范围筛选不等于文本搜索，不应该触发所有目录强制展开。

### 7.5 清空、取消与重置的边界

| 动作 | 改变 | 不改变 |
|---|---|---|
| 清除搜索 | 定位查询和结果列表 | 显式筛选、已提交文件焦点 |
| 清空筛选 | 目录／文件类型等显式条件 | 当前浏览目录、导航历史 |
| 退出文件关系 | 恢复进入前工作状态 | 来源筛选和来源视角 |
| 返回 | 恢复上一条导航快照 | 仓库分析结果 |
| 适应当前内容 | 画布平移与缩放 | 选择、筛选、粒度、跳数 |
| 返回仓库概览 | 开始查看仓库根概览，并保留可返回来源 | 分析结果本身 |

不建议提供一个没有范围说明的“全部重置”，让用户猜测会丢失哪些状态。

## 8. 文件选择与关系浏览

对应问题：I-01、I-03、I-09、I-11、I-16。

### 8.1 统一选择入口

侧栏文件、搜索结果、分析结果、关系明细和画布文件节点，应遵守同一套文件选择规则：

1. 验证目标仍属于当前分析结果。
2. 保存当前来源上下文。
3. 进入文件关系状态，确定关系方向和跳数。
4. 在画布显示目标及关联文件，在侧栏展开目标路径。
5. 更新详情栏与可操作明细。
6. 仅在需要时调整视角。

若目标因重新分析而已删除，应说明“该文件不在最新分析结果中”，提供返回来源；不能保持一个无效路径和旧数量。

### 8.2 关系方向的默认值

| 进入来源 | 初始关系方向 |
|---|---|
| 普通侧栏选择、搜索、枢纽排行 | 谁依赖它，默认 2 跳 |
| 入口点列表 | 它依赖谁，默认直接依赖 |
| 在关系视图继续选择关联文件 | 保留当前方向和跳数 |
| 循环组成员 | 保留循环组来源；单文件关系按当前明确模式展示 |

来源决定的初始值必须在控件中明确体现，不能让用户把不同方向下的同一个数字作比较。切换方向应保留焦点文件，不清除浏览历史。

### 8.3 两个方向的语义

- “它依赖谁”：沿文件依赖方向查看，1 跳为它直接依赖的文件。
- “谁依赖它”：沿反向依赖查看，1 跳为直接依赖它的文件。
- 跳数采用最短关系路径，不把重复路径计为多个文件。
- 焦点文件不计入关联文件数量；即使存在自环，也不把自己算成额外受影响文件。
- “全部”表示本次已解析依赖图中的全部可达文件，不表示已证明真实运行时所有影响。

默认延续分跳数查看，避免无限传播掩盖文件之间的区别。

### 8.4 影响模式与循环模式不要混用边规则

影响分析中，可以继续优先展示逐跳传播关系，避免同层横向关系干扰阅读。

循环组检查中必须允许查看组内完整依赖，包括同层关系和自环，否则循环成立的关键关系可能被影响模式的规则排除。

模式切换时说明当前展示的是“影响传播关系”还是“循环组内部依赖”，不能把同一套高亮结果解释成两种不同结论。

### 8.5 从数字进入明细

建议让详情栏中的以下内容可继续操作：

| 摘要 | 打开内容 | 继续操作 |
|---|---|---|
| N 个文件受影响 | 对应方向、跳数、范围的文件列表 | 选择文件、查看关系路径、返回 |
| N 个直接依赖 | 直接依赖文件列表 | 继续阅读某个文件 |
| N 个导出符号 | 导出符号及仓库内引用信息 | 查看具体导出符号 |
| N 个疑似未被使用的导出符号 | 疑似结果及适用豁免解释 | 核查证据，不提供未经确认的删除动作 |

数字对应的列表必须使用同一统计集合。不能点击“2 跳内 19 个文件”，却打开全部 21 个且没有说明。

“找不到仓库内引用”与经过豁免规则后的“疑似死代码”不是同一集合，详情与分析面板需要说明差异，不能共用一个含糊标签。

## 9. 分析面板与问题排查

对应问题：I-04、I-08、I-15、I-16。

### 9.1 打开规则

- 通用“分析”按钮恢复上次访问的分类和位置；首次打开可默认枢纽排行。
- 点击某个仓库摘要，明确进入对应分类。
- 点击告警“查看清单”，进入解析报告中的相应清单，而不是仅打开面板。
- 上述操作不应自动取消画布文件选择。
- 分析数据默认是仓库级，面板应明确说明；如果以后支持范围内分析，需要独立的范围选择。

### 9.2 结果预览与图中定位分离

推荐的第一轮方案：继续使用现有分析面板，不额外引入新的常驻布局。

1. 点击结果行，在同一面板内进入结果预览，不立即关闭面板。
2. 预览提供“在图中定位”明确动作。
3. 执行定位后关闭面板，进入相应文件或循环组工作状态。
4. 来源快照保留分类、列表位置和当前结果。
5. “返回分析结果”恢复这份快照。

在模态面板打开时，不允许鼠标或键盘继续操作被遮挡的背景控件。面板内详情使用同一层导航，不叠加多个模态窗口。

### 9.3 循环组检查

循环组是一个业务对象，不是随意挑选一个代表文件。

- 点击组：查看整组摘要、成员和组内关系。
- 点击成员：选择准确成员，不能统一跳到 `cycle[0]`。
- “在图中查看整组”：显示所有成员，不受进入前目录筛选截断。
- “查看成员的依赖／影响”：进入该成员的文件关系状态，保留返回该循环组的入口。
- 单文件自环按 1 个循环组、1 个成员说明，不描述为多文件互相依赖。
- 循环组表示互相可达集合，不等于只有一条唯一的简单环路径。

### 9.4 疑似死代码检查

每个结果至少回答：

- 哪个文件的哪个导出符号被列出。
- 当前分析找到了哪些仓库内引用，或为什么未找到。
- 是否涉及命名空间导入、入口点等豁免规则。
- 哪些情况工具无法确认，例如动态使用和仓库外消费方。

从结果进入文件时保留导出符号身份，不只显示文件总计。

当疑似结果为零时，应写“未发现符合当前规则的疑似死代码”，而不是“所有导出符号都有引用”；零结果也可能来自豁免，并不证明每个导出符号都存在显式引用。

### 9.5 连续浏览

- 当前分类内支持上一项／下一项。
- 结果顺序在同一次检查期间保持稳定。
- 返回列表后恢复选中项和滚动位置。
- 筛选或重新分析改变结果集时，说明当前条目是否仍存在；不要静默跳到无关条目。
- 枢纽排行如果只展示前 40 项，需要写明“当前显示前 40 项”，并提供查看更多或完整列表。
- 大列表分页或虚拟滚动不应改变点击对象、键盘焦点与返回位置。

## 10. 统计、状态与控件语义

对应问题：I-06、I-11。

### 10.1 统计口径

| 内容 | 推荐表达 | 避免的表达 |
|---|---|---|
| 全部代码文件 | 仓库共 2209 个代码文件 | 把全部文件写成 2209 个枢纽文件 |
| 枢纽入口 | 依赖排行；或按明确标准统计的枢纽数量 | 未定义阈值却暗示每个文件都是枢纽 |
| 循环组数 | 77 个循环组 | 与成员数都叫“循环依赖” |
| 循环成员数 | 涉及 286 个文件 | 不写单位的 286 |
| 当前影响 | 2 跳内 19 个文件；全部 21 个 | 不说明当前跳数的“19 个受影响” |
| 当前范围 | 当前目录内 8 个，目录外 11 个 | 把范围内数量当作全仓库结论 |
| 导出符号 | 26 个导出符号，分布于 N 个文件 | 把符号数与文件数混用 |
| 孤岛 | 在当前已解析依赖图中无依赖连接 | 死文件、可以删除 |

用户截图中的 77 和 286 是不同统计单位，不应为了让数字一致而更改算法；应把对象和范围说清。

### 10.2 范围内外数量示例

假设焦点文件在 2 跳内关联 19 个其他文件，其中当前浏览目录内 8 个、目录外 11 个：

- 摘要：2 跳内 19 个文件，当前目录内 8 个、目录外 11 个。
- 默认文件关系视图展示焦点文件加 19 个关联文件。
- 目录外 11 个不是遗漏结果，也不是解析失败。
- 不限跳数的 21 个应单独标为全部影响数量。
- 如果启用范围内显示限制，不能仍暗示画布已展示全部 19 个。

### 10.3 控件可用性

| 控件 | 适用状态 | 不适用时 |
|---|---|---|
| 目录粒度 | 工程浏览 | 在文件关系中通过“返回目录浏览”切换，不静默丢失焦点 |
| 关系方向和跳数 | 文件关系 | 未选文件时不可用，并说明需要先选择文件 |
| 仅显示筛选结果 | 工程浏览且存在显式筛选 | 说明前置条件 |
| 循环文件标注 | 文件视图 | 目录聚合尚未定义语义时不提供假生效操作 |
| 查看循环组 | 存在循环分析结果 | 无结果时说明未检测到，而非显示无响应入口 |
| 分析 | 有成功分析结果 | 尚未分析时不可用，并指向打开目录或示例 |
| 重新分析当前工程 | 有可重新读取的数据来源 | 权限失效时说明需要重新选择目录 |

循环标注与循环筛选是不同动作：标注不改变当前文件集合，“查看循环组”才进入问题检查。

## 11. 画布交互与自动视角

对应问题：I-01、I-12。

本节只定义用户操作与系统自动行为，不调整视觉风格。

### 11.1 自动移动的触发边界

- 首次进入新工程、目录或关系视图，可以执行一次适应当前内容。
- 目标已在可用视口内时，选择它不应引起无意义平移。
- 用户已经手动平移、缩放或拖动节点后，后台布局完成不能再次抢走视角。
- 返回旧视图优先恢复旧视角，不重新执行首次自动取景。
- “可用视口”应扣除覆盖内容的面板和工具区域，不能把节点放在遮挡后面还判为可见。

### 11.2 零节点、单节点与少量节点

- 零节点：显示原因和恢复动作，不运行取景。
- 单节点：限制最大缩放，使文件可辨识，不把节点填满画布。
- 少量节点：同样限制自动缩放，不因数量骤减造成极端视角跳变。
- 布局尚未稳定时，不连续多次自动适应。

### 11.3 手动视角操作

- “适应当前内容”只改变视角，不重置筛选、焦点或关系跳数。
- 如保留“查看全部节点，含孤岛”，需与默认聚焦主体的操作明确区分。
- 小地图点击只平移视角，不更改选择和业务范围。
- 从图中选择其他关联文件形成导航；拖动和平移不形成一长串业务返回记录。
- 点击画布空白不默认清除范围；若要退出文件关系，使用明确的退出动作。

## 12. 加载、失败与空状态

对应问题：I-13、I-14、I-15。除单节点取景外，本节主要为源码检查后的建议，尚未完成真实异常场景实测。

### 12.1 分析生命周期

| 阶段 | 应提供的信息 | 用户可执行的动作 |
|---|---|---|
| 选择目录 | 浏览器授权与选择结果 | 取消选择；保留原工程 |
| 遍历目录 | 正在扫描；已发现文件数，若可获得 | 请求取消 |
| 读取与解析 | 已处理／总文件数，及当前阶段 | 请求取消 |
| 构建分析结果 | 正在计算依赖与指标 | 请求取消；不要假装已经完成 |
| 准备图形布局 | 分析已完成、画布仍在准备 | 可先查看已就绪的结果明细 |
| 完成 | 工程名称、分析版本、必要告警 | 浏览、重新分析、切换工程 |
| 失败 | 失败阶段、已知原因、保留了什么 | 重试、重新选择目录、返回旧结果 |

未知总量时不显示伪造百分比；阶段进度与整个任务进度要区别开。

### 12.2 保留旧结果直到新结果成功

推荐行为：

1. 新扫描开始时保留上一次成功结果及其浏览上下文。
2. 明确显示正在分析哪个新目录，旧画面仍属于哪个旧结果。
3. 新分析成功后一次性切换工程及结果，并清除不适用于新仓库的选择与导航历史。
4. 新分析失败或取消时恢复旧工作状态。
5. 如果之前没有结果，则回到可重试的起始状态。

不能出现新工程名称搭配旧工程依赖数量的混合状态。

### 12.3 取消与重新分析

- 浏览器目录选择取消不算错误，不清空旧工程。
- 应提供“重新分析当前工程”，不要求用户每次通过“换一个目录”重新选择同一位置。
- 取消后，晚到的旧任务结果不得重新覆盖当前页面。
- 若某阶段不能立即中断，明确显示已请求取消，并在安全点结束；不能先宣称已取消，却继续把结果提交给界面。
- 修改读取并发等参数后，说明仅下次分析生效，并提供对应重分析动作。
- 同一时刻只接受一个明确的结果提交；重复点击不能产生不可区分的并行扫描。

### 12.4 空状态与恢复动作

| 场景 | 应表达的事实 | 推荐恢复动作 |
|---|---|---|
| 还未打开工程 | 尚无分析结果 | 打开目录、看示例 |
| 目录没有支持的代码文件 | 扫描完成，但无可分析文件 | 选择其他目录、查看支持范围 |
| 搜索零命中 | 当前查询没有匹配文件 | 修改或清除搜索；必要时切全仓库搜索 |
| 显式筛选零命中 | 当前条件组合没有文件 | 逐项移除或清空筛选 |
| 当前方向没有关联文件 | 在已解析图中未发现这种关系 | 切换方向、查看导出信息、返回 |
| 文件在浏览范围外 | 文件存在，只是不属于来源范围 | 临时查看关系、浏览所在目录、返回 |
| 文件在新结果中消失 | 旧导航目标不再有效 | 返回来源、重新搜索 |
| 未检测到循环组 | 当前分析没有循环组结果 | 返回浏览；不推断所有运行时依赖都无环 |
| 无疑似死代码结果 | 没有符合当前规则的疑似项 | 查看规则与豁免说明 |
| 部分解析失败 | 可用结果存在，但图可能缺少依赖 | 直接查看对应失败清单、重新分析 |

### 12.5 告警应直达可处理信息

“查看清单”应打开对应分类并定位到对应内容。关闭告警仅关闭提醒，不删除报告内容。

解析失败应区分已知工具限制、权限或读取问题、可能缺少配置等原因；不要把所有情况都归责为用户工程错误。

## 13. 键盘与焦点行为

对应问题：I-07、I-10、I-11。

### 13.1 最低可用操作

| 区域 | 建议键盘行为 |
|---|---|
| 文件搜索 | 上下键移动结果，Enter 选择，Escape 先关闭结果再按既定规则清词 |
| 目录树 | 上下键移动，右键展开／进入子项，左键折叠／回父项，Enter 选择文件或执行目录主动作 |
| 分析分类 | 可通过键盘切换，并明确当前分类 |
| 分析结果 | 可移动到每项，Enter 预览，明确动作执行图中定位 |
| 文件关系明细 | 与结果列表相同，可继续选择关联文件 |
| 模态分析面板 | 打开时焦点进入；Tab 不进入背景；关闭后回到触发入口 |
| 侧栏宽度调整 | 保留现有方向键、加速和复位行为 |

图上无法通过键盘直接操作的关系，必须在关系明细中提供等价路径；不能以“有一个分析表格”代替完整的文件关系导航。

### 13.2 Escape 的优先级

每次按键只关闭最上层相关状态：

1. 先关闭当前搜索候选或临时弹出内容。
2. 再关闭分析面板等最上层容器，并恢复焦点。
3. 在没有文本编辑和弹出层时，才允许退出当前文件关系或取消明确选择。

不能一次 Escape 同时清搜索、关面板、取消选择和清筛选。存在文本输入法组合状态时，不把用于结束输入的按键误解释为导航动作。

### 13.3 其他输入原则

- 不接管文本编辑、浏览器系统或操作系统的已有快捷键。
- 核心动作不能仅通过悬停、双击或右键触发。
- 无效操作应明确不可用及原因，不能让键盘进入后得到无反馈点击。
- 面板关闭后的焦点目标若已不存在，回到所属区域的稳定入口，而不是页面起点或不可见元素。

本节是交互要求，不是已完成的无障碍合规声明。

## 14. 关键状态转换表

| 事件 | 状态变化 | 必须保留 | 用户反馈 |
|---|---|---|---|
| 输入搜索词 | 只更新定位查询与结果 | 已提交焦点、图范围、视角 | 匹配数量、完整路径 |
| 提交搜索结果 | 进入文件关系 | 原范围、筛选、搜索结果位置 | 正确目标及关系可见 |
| 点击目录节点 | 更新浏览目录 | 原目录视图快照、显式条件 | 当前位置、返回入口 |
| 点击文件 | 更新焦点并进入关系状态 | 来源快照 | 文件路径、方向、跳数、统计 |
| 点击相同文件 | 不改变业务状态 | 全部 | 保持选择，不跳动 |
| 切换关系方向 | 更新关系方向 | 焦点、来源范围 | 方向与数量同步更新 |
| 修改跳数 | 更新关系集合 | 焦点、方向、导航来源 | 当前跳数数量与全部数量 |
| 从关系中选择文件 | 新文件成为焦点，新增导航记录 | 原文件及其关系设置 | 可返回原文件 |
| 查看循环组 | 进入循环组检查 | 原分类和结果位置 | 全组成员和内部依赖 |
| 选择循环成员 | 精确选择该成员 | 循环组来源 | 点谁就到谁 |
| 图中定位分析结果 | 关闭面板，进入对应工作状态 | 分类、预览、条目、滚动 | 返回分析结果入口 |
| 清空筛选 | 仅清显式条件 | 当前浏览目录、历史 | 条件消失，范围结果更新 |
| 返回 | 恢复上一条有效快照 | 当前分析结果 | 原位置与上下文恢复 |
| 适应当前内容 | 仅更新视角 | 所有业务状态 | 当前对象进入可用视口 |
| 新工程分析成功 | 切换整个结果版本 | 可独立保留的用户偏好 | 新工程所有区域一致 |
| 新分析失败或取消 | 保留旧成功结果 | 旧浏览上下文 | 失败／取消原因与恢复动作 |

“返回”不需要记录每次悬停、鼠标移动、文字输入或布局帧。导航历史只记录用户有意义的对象与位置变化；关系方向和跳数作为对应导航项的状态保存。

## 15. 分阶段落地建议

### 15.1 第一阶段：修复核心流程断点

目标：用户能可靠地找到对象、检查关系、继续进入并返回。

建议顺序：

1. 定义统一的文件／循环组选择规则，以及范围外目标的显示方式。
2. 分离搜索定位与显式筛选，停止搜索词对关系集合的隐式限制。
3. 建立目录下钻、文件继续浏览、分析结果定位共用的来源与返回规则。
4. 修复循环组成员精确选择，保留分析分类和列表位置。
5. 明确核心统计单位及不适用控件的反馈。
6. 补齐上述新增或调整路径的键盘和焦点行为。

范围边界：不同时改造图算法、整体视觉风格、所有布局参数或增加源码编辑能力。

### 15.2 第二阶段：补齐阅读与异常恢复

- 增加“它依赖谁”与关系明细，承接从入口点阅读的任务。
- 让影响与导出摘要可进入对应明细。
- 完善循环组和疑似死代码的预览与解释。
- 限制少量节点自动取景，稳定返回视角。
- 提供零结果恢复、当前工程重新分析、取消和旧结果保留。
- 完成告警到报告清单的精确跳转。

### 15.3 第三阶段：熟练使用效率

- 分析结果上一项／下一项与更完整的列表浏览。
- 可选当前范围搜索、范围内关系显示。
- 根据真实仓库测试调整默认粒度策略。
- 可配置快捷键、同一结果版本内的更完整视角恢复。

不建议在第一阶段同时增加任意多选、多文件影响并集、可编辑图、持久化工作会话或跨仓库历史。这些能力会明显扩大状态组合，应在单对象主流程稳定后单独评估。

### 16.1 第一轮发布门槛

至少完整通过两条端到端路径：

1. 目录概览 → 搜索文件 → 查看 2 跳影响 → 进入关联文件 → 返回原文件 → 返回原目录概览。
2. 循环分析列表 → 预览某组 → 选择任意成员 → 图中定位 → 返回原循环组 → 返回原列表位置。

两条路径都不应要求用户手动清空搜索、补切粒度、解除隔离或重新寻找列表位置；同样应存在可完成的键盘路径。

### 17.2 建议采用的默认决策

为避免实施时反复分叉，本建议以以下默认方案展开：

1. 搜索是定位，不是画布硬筛选。
2. 选择文件进入独立文件关系状态，默认覆盖本次已解析全仓库关系。
3. 浏览目录、显式筛选与临时关系查看分离；返回恢复来源。
4. 目录粒度相对当前浏览目录解释。
5. 点击循环组看整组，点击成员看准确成员。
6. 分析行先预览，显式“在图中定位”才关闭面板。
7. 通用分析入口记住上次分类，具体摘要和告警执行精确跳转。
8. 重复点击当前文件保持选择；退出通过明确动作完成。
9. 新分析成功后才替换旧成功结果。

这些是产品建议而非已经获准实施的决定。若后续不采用其中某项，应同时调整相应状态转换和验收标准，避免只改一处造成新的不一致。
