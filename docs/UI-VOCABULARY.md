# UI 区域词汇表

界面按**区域**划分。同一个区域，组件名、CSS 类名、口头称呼三者一致——
这样「把图例挪到画布工具条右边」这种要求不需要再解释指的是哪块。

整屏三段栅格，主视图**不产生页面滚动**：侧栏和画布就是页面。

## 区域 → 组件 → CSS

| 区域 | 说的时候叫 | 组件 | CSS 根类 |
|---|---|---|---|
| 顶栏 | 顶栏 | —（内联于 App） | `.app-bar` |
| 警告条 | 警告条 | — | `.banner` |
| 工作区 | 工作区 | — | `.workspace` |
| 工程目录侧栏 | **侧栏** | `ProjectSidebar` | `.sidebar` |
| 图幅 | **画布** | `GraphCanvas` | `.canvas` |
| 位置索引图 | **小地图** | （画布内） | `.canvas-locator` |
| 图幅外框 | **图谱面板** | —（App 内联） | `.graph-panel` |
| 选中项单行 | **详情栏** | `DetailRail` | `.detail-rail`（图幅内） |
| 画布设置条 | **设置条** | （画布内） | `.canvas-tools` → `.control-group` |
| 画布文件名 | **文件名标签** | `nodeLabels.ts` | （canvas 绘制，无 DOM 节点） |
| 分析抽屉 | **分析面板** | `NotesDrawer` | `.notes` |

## 视觉概念：一张地图图幅

制图学的部件和这个工具需要的东西一一对应，所以不是比喻，是直接借用：

| 制图学 | 这里 |
|---|---|
| 图幅内框线（neatline） | `.canvas-neatline` — 把画布和页面分开 |
| 位置索引图（locator inset） | `.canvas-locator` — 全图缩略 + 视口矩形，点击跳转 |
| 图例（legend） | `.canvas-legend` — 目录配色 + 循环依赖 |
| 地名注记（label） | 画布文件名 — 只在聚焦时出现，打不赢碰撞就不画 |
| 索引（index） | `.sidebar` — 按目录组织的文件清单 |
| 图幅注记 | `.notes` — 收进抽屉的全部分析表格 |

## 命名规则

- **部件**：`区域-部件` — `sidebar-row`、`canvas-stage`、`canvas-tooltip`
- **状态修饰**：`区域-部件--状态` — `sidebar-row--selected`、`sidebar-row--dimmed`
- **跨区域复用的通用件**保持无前缀，但必须是明确的名词：
  `card`（卡片容器）、`card-title`、`stat`（数字磁贴）、`scroll-box`（定高滚动容器）、
  `data-table`、`hint`（灰色注释文字）、`legend` / `legend-item`、
  `segmented`（一组互斥选项挤成一条，选中态加 `.is-on`）、
  `chip`（可切换的筛选项，选中态 `.chip--on`）、`metric`（行内数字）、
  `inline-field`（标签 + 控件 + 说明同一行）

## 数字排版

**这是数据工具，数字就是内容。** 两条规则：

1. **全局 `tabular-nums`**（设在 `body` 上）。比例字距下 `1` 比 `8` 窄一大截，
   换个仓库整行文字会左右跳动，侧栏那一列入度也对不齐。
2. **数值比它的单位亮一档**。「31 个代码文件」里真正的信息是 31，
   「个代码文件」只是单位。用 `.metric`（行内）或 `.stat`（磁贴），
   数值 `--ink-2`、单位 `--ink-3`。

曾经只有详情栏和抽屉表格这么做，顶栏、图例、提示框没跟上——
**同一个界面里两套数字排版，比全都不做还难看**。

## 主 chrome 只放主操作

顶栏右侧只有「打开目录 / 换一个目录」。

并发数曾经放在那里，紧挨着主操作按钮。它是做性能对比时加的调试旋钮，
用户没有理由动它，却占着整个界面最贵的位置——已挪进「分析 → 解析报告」，
和它影响的耗时数字放在一起。

**判据：一个控件如果只有开发者会动，它就不该出现在主 chrome 上。**

**禁止再出现的类名**：`.row`、`.list`、`.tip`、`.split`、`.panel`——
过于通用，看不出归属，且极易与后续组件冲突。它们已在本次重构中全部替换。

## 圆角分级

**所有东西同一个圆角是模板感的来源。** 按层级分四档：

| 令牌 | 值 | 用在 |
|---|---|---|
| `--r-panel` | 14px | 侧栏、画布、详情栏、分析抽屉这类主面板 |
| `--r-card` | 10px | 抽屉内部的内容卡片 |
| `--r-control` | 8px | 按钮、输入框、下拉、小地图、工具条 |
| `--r-row` | 6px | 侧栏行、表格悬停行 |

配套的层次色：`--plane`（页面）< `--board`（底板）< `--panel`（面板）< `--panel-2`（面板内的凹槽）。
**阴影只给真正浮起来的东西**（分析抽屉），面板之间靠 1px 边框和底色差区分——
给每张卡都加一层灰色投影是廉价感的另一个来源。

## 侧栏宽度可拖拽

分隔条 `.resize-handle` 是 `role="separator"`，默认隐形，悬停/聚焦/拖动时才出现一条 2px 线。

- 拖拽用 Pointer Capture，拖出窗口再松手也不丢事件
- 键盘可达：`←` `→` 调 16px，`Shift` 加速到 48px，`Home` 复位
- 双击复位
- 宽度存 `localStorage`，范围 190–560px

## 两条视觉硬约束

1. **`--stage` 必须是 `#1a1a19`。** 分类色是针对这个表面色验证过的（ADR-011），
   改了就得重跑 `validate_palette.js`。页面底色（`--plane`）比图幅暗，让图幅浮起来。
2. **强调色只用于「当前选中/聚焦」。** 按钮、标签、导航一律用墨色和细线。
   到处都是同一个亮色是廉价感的主要来源——这是这次改版最主要的一条纪律。
   影响范围的蓝环用 `globalAlpha` 按跳数递减（1 跳最实，3 跳最淡），
   这不算破例：同一个强调色的深浅编码距离，而不是引入第二个亮色。

## 组件文件位置

```
src/ui/
├── ProjectSidebar.tsx   侧栏
├── GraphCanvas.tsx      画布（含小地图）
├── DetailRail.tsx       详情栏
├── NotesDrawer.tsx      分析面板（枢纽/入口/循环/死代码/孤岛/报告）
└── palette.ts           配色（见 ADR-011）
```

`App.tsx` 只做三件事：状态编排、数据加工（useMemo）、区域组装。
**不再包含任何具体区域的渲染细节**——要改某个区域，直接打开对应文件。
